# 会话上下文只放进程内存，不落盘

## 决定

`createAgentSession({ sessionManager: SessionManager.inMemory() })`。会话上下文只活在 Node 进程里，10 分钟无活动即 `dispose()`，上限 5 个并发。

PG 里的 `messages` 表只是**展示用副本**，供后台与导出读取，**不是模型上下文的来源**。

## 为什么不持久化

Pi 支持把 session 落成 JSONL，也能从 JSONL 恢复。我们主动放弃了：

| 维度 | 落盘 | 内存 |
|---|---|---|
| 会话数增长后的清理 | 要写清理任务，否则磁盘涨 | 无 |
| 冷启动恢复 | 读盘 + 反序列化，几百毫秒 | 无（直接新建） |
| 上下文一致性 | 文件与 PG 两份副本，必然漂移 | 单一来源 |
| 进程重启 | 会话可续 | **进行中的会话丢失** |

客服会话平均 6 轮、时长 3–5 分钟，**重放的成本低于读盘的成本**。

## 代价

进程重启会丢进行中的会话。这一点必须写进 README「已知限制」，不能让运维以为是 bug。

## 会怎么被推翻

如果出现"用户聊到第 8 轮，服务刚重启，上下文断了"的客诉，再改回 JSONL 或 Redis 持久化。届时 `core/agent.ts` 的会话池要重写，约半天。
