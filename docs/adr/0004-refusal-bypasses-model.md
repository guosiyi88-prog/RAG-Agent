# 拒答话术由后端下发，不经模型

## 背景

客服 AI 最大的风险是说错话。需要一种机制：模型没有依据时必须闭嘴，且闭嘴的方式可控。

## 决定

三段式，责任切干净：

1. **模型层**：prompt 硬约束——资料不足时**只输出** `NO_ANSWER` 四个字母，不解释、不道歉
2. **后端层**：检测到 `NO_ANSWER` 或本轮引用为空 → **丢弃模型输出**，直接用 `REFUSAL[lang]` 常量下发，并建工单
3. **前端层**：渲染固定话术 + 工单小卡

同时，任何 `[n]` 角标若不在本轮候选集内，整条答案降级为拒答。

## 为什么不靠模型自觉

模型说"我不知道"有 100 种说法：`抱歉` / `无法确认` / `建议咨询专业人员` / 直接沉默。靠正则或语义判断，误判率不可接受。

用固定哨兵串 `NO_ANSWER` 做字符串匹配，判定 100% 确定。

## 顺带解决的三个问题

| 问题 | 不这么做的后果 |
|---|---|
| 拒答延迟 | 让模型再生成一句"礼貌地说明不知道"，+3s |
| 话术可控 | 模型可能答"你可以找第三方维修"，法务风险 |
| 多语成本 | 5 份话术进 prompt 会挤占上下文，且必然漂移 |

## 代价

拒答话术在 5 个语种里都是**人工定稿**，不机翻。这是唯一允许在 i18n 里写长句的地方。

## 会怎么被推翻

几乎不会。如果将来要"软拒答"（先给部分信息再说需要确认），也是在这三段式外面套一层，内核不变。
