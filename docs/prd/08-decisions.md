### 1.1 D2 的诚实说明

"不砍" 与 "1 天" 在数学上冲突：

- 16 项 P0 的最小实现约 20 小时（含联调、评测、录屏）
- 一人一天按 12 小时计，缺口 8 小时

本 PRD 不给模糊答案，给出三条可执行路径（`07.4`），请选一条：

| 路径 | 时长 | 人力 | 结果 |
|---|---|---|---|
| Plan A | 16h | 1 人 | 16 项全交 |
| Plan B | 12h | 2 人 | 16 项全交（需 H0 并行定契约） |
| Plan C | 8h | 1 人 | 6 项 + 完整闭环 |

**未选择即默认 Plan C**（保命优先）。

## 3. 勘误表（前序文档的错误，逐条记录以免重犯）

### 3.1 `docs/output/task.md` v3 的错误

| # | 错误 | 实际情况 | 证据 |
|---|---|---|---|
| E1 | 用 `pi --mode rpc` 子进程池做架构 | SDK 是进程内 TS，无 `--mode`/`--no-builtin-tools`/`--session-dir` | [SDK 文档](https://pi.dev/docs/latest/sdk) |
| E2 | 自定义工具用 `customTools` 直传 | 必须经 extension 的 `pi.registerTool()` 注册；`tools:[]` 只做选择 | `examples/sdk/05-tools.ts` 注释 |
| E3 | 认为默认 system prompt 可用 | 默认面向编码助手，不改会去读文件、改代码 | `examples/sdk/03-custom-prompt.ts` |
| E4 | 历史从 PG 塞进 prompt | `SessionManager` 是上下文权威，给 `agent.state.messages` 赋值无效 | SDK 文档原话 |
| E5 | 在 `agent_before_settle` 里发消息出拒答话术 | 文档未保证该阶段能再触发模型 → 演示会卡 8 秒 | extensions 文档 |
| E6 | 单会话成本 < $0.01 | 按 6 轮真实口径约 $0.0126，上限应为 $0.03 | 算术重算 |
| E7 | hit@5 ≥ 70% 未定义 | 未定义 = 不可测 = 假指标 | 本 PRD `07.2` |
| E8 | 用户端无鉴权 | 匿名即可刷建单 → 工单灌库 | 本 PRD `06.1` |
| E9 | 12 小时能装下 16 项 | 真实约 20 小时 | `07.4` |
| E10 | 跨语种检索未设计 | 五语副本会互相稀释，`tsvector('simple')` 不做词干化 | 本 PRD `04.6` |

## 4. 本次拷打中被推翻的假设

按"如果不改，什么时候会炸"排序：

| # | 原假设 | 为什么错 | 会在什么时候炸 |
|---|---|---|---|
| 1 | 可以边写边决定技术细节 | SDK 的三条硬约束（C1/C2/C3）任一踩中都要返工 | H3 时才发现在改架构 |
| 2 | 五语只是多翻几份文档 | 副本稀释会让 top5 全是同义重复，hit@5 直接腰斩 | 评测时才发现 |
| 3 | 拒答靠 prompt 就行 | 模型说"我不知道"有 100 种说法，无法判定 | 演示时答了不该答的 |
| 4 | 12 小时够 | 每轮加功能都没重算，累计缺口 8 小时 | 最后一晚 |
| 5 | 引用角标前端渲染即可 | 后端不校验就是给模型造假的机会 | 客户第一次点开角标 |
| 6 | 匿名用户没风险 | 建单接口敞开 = 数据污染 | 上线第一天 |
| 7 | 凭据/遥测是小事 | 欧洲客户数据出境是法律问题 | 法务介入时 |
