## 2. 总验收指标

| 指标 | 定义（可执行） | 通过线 | 验证命令 |
|---|---|---|---|
| hit@5 | 召回 top5 中任一 `doc_id == qa_gold.expect_doc_id` 的题占比 | ≥ 70% | `npm run eval` |
| 引用合法率 | 有引用的答案里，所有 `[n]` 都落在本轮候选集的比例（非法角标会整条降级为拒答，见 `06` §5.1 ④） | **= 100%**（低于即校验失效） | `npm run eval` |
| 拒答准确率 | `should_refuse` 题中输出固定话术且建单的比例 | ≥ 90% | `npm run eval` |
| 首字延迟 | 发送 → SSE 首个 `delta` | P95 < 3s | 手工 + `skill: perf` |
| 单轮延迟 | 发送 → `done` | P95 < 8s | 手工 |
| 故障码直查 | 输入 → 结果卡 | P95 < 1s | `npm run perf:fault` |
| 单会话成本 | `conversations.total_cost_usd` ÷ 会话数 | < $0.03 | `SELECT avg(total_cost_usd) FROM conversations` |
| 健康检查 | `/healthz` 四项全 ok | 100% | `curl -s localhost:8000/healthz \| jq .ok` |

## 4. 角色（开发时用于判断取舍）

| 角色 | 优先级 | 取舍原则 |
|---|---|---|
| P1 欧洲安装商（手机、现场） | **最高** | 宁可少功能，不能慢、不能错 |
| P2 终端业主（手机、夜间） | 中 | 能用就行 |
| P3 售后坐席（桌面） | 高 | 队列和详情必须顺，其他可后补 |

**冲突时的裁决顺序**：正确性 > 速度 > 功能数 > 美观。

## 6. 不做什么比做什么更重要

以下行为**视为交付失败**，即使功能都能跑：

| 反模式 | 为什么失败 |
|---|---|
| 引用角标是前端编的编号 | 客户点开发现对不上，产品信任归零 |
| 拒答靠模型说"我不知道" | 有 100 种说法，无法判定，必然答错 |
| 检索不达标靠调 prompt 掩盖 | 数据骗人，上线即崩 |
| 把 `read/bash/edit/write` 留给模型 | 客服机器人去读服务器文件 |
| 用户端无鉴权 | 工单被灌库 |
| 声称五语但只有中文 | 演示时一问就穿 |
