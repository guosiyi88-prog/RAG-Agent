# 17 · 给 AI 的操作纪律

> 本文件是开发 AI 的**行为约束**。每张任务卡开工前重读一遍。

## 1. 你在这个项目里的角色

你是一个按规格实现的工程师，不是架构师。**规格已经定完了。** 你的工作是把 `docs/prdv1.1/` 翻译成代码，而不是重新设计它。

遇到规格没写的地方，按 §7 的裁决规则处理，**不要停下来问人**（除非触发了 §8 的阻塞条件）。

## 3. 十条硬纪律

| # | 纪律 | 违反后果 |
|---|---|---|
| 1 | 文件路径必须与 `02-architecture.md` §2 的文件树**完全一致** | 后续卡找不到文件 |
| 2 | 接口字段名必须与 `04`/`05` 完全一致（`snake_case`） | 前后端对不上 |
| 3 | 常量集中在 `src/config.ts`，禁止散落魔法数 | 调参时漏改 |
| 4 | 只有 `config.ts` 读 `process.env` | 无法审计配置 |
| 5 | `tools:[]` 里**绝不能**出现 `read`/`bash`/`edit`/`write` | 客服机器人去读服务器文件 |
| 6 | 拒答话术**不经模型**，后端直接下发 | 延迟 3s 且话术不可控 |
| 7 | 引用角标必须后端校验 `n ∈ 候选集` | 模型编造角标直接发给客户 |
| 8 | 检索 SQL 必须带 `lang = any(...)` | 五语副本互相稀释，hit@5 腰斩 |
| 9 | RRF 分数**必须归一化**后再与 `MIN_SCORE` 比较 | 100% 拒答 |
| 10 | 用户端（`index.html` / `user.js`）所有可见文字走 `data-i18n`，禁止硬编码；坐席端例外，只做中文 | 五语失效 |


## 5. 禁止的"聪明"

以下行为看似省事，实际会让验收失败：

| 禁止 | 应该 |
|---|---|
| 给 `ADMIN_TOKEN` 一个默认值 | 缺失就 `process.exit(1)` |
| 用 `EventSource` 做 SSE | 用 `fetch` + `ReadableStream` |
| 把 RRF 原始分直接和 0.30 比 | 先归一化（`07` §5.1） |
| 检索不好就改 prompt | 按 `07` §10 调参 |
| 让模型自己判断"不知道" | 固定哨兵 `NO_ANSWER` + 后端替换 |
| 前端拼角标 | 后端给 `citations` 事件，前端只渲染 |
| 用 ORM / LangChain / 队列 | 手写 SQL，Pi 直接跑 |
| 引入构建链（webpack/vite/tsc 产物） | `node --experimental-strip-types` 直接跑 |
| 加 ESLint/Jest | 只保留 `scripts/eval.ts` |
| 把 `sql/001_init.sql` 拆成多个 migration | 一期一次建完 |
| 用 emoji 当图标 | 内联 Lucide SVG |
| 硬编码中文文案 | `i18n.json` + `data-i18n` |
| 会话跨请求持久化到磁盘 | `SessionManager.inMemory()` |

## 6. 代码风格（最小集）

| 项 | 规则 |
|---|---|
| 模块 | ESM（`import`/`export`），文件后缀写 `.ts` |
| 命名 | 变量/函数 `camelCase`，类型 `PascalCase`，常量 `SCREAMING_SNAKE` |
| SQL 字段 | `snake_case`，与 PG 一致 |
| 类型 | `strict: true`，禁止 `any`（确需时写 `unknown` + 收窄） |
| 错误 | 只抛 `AppError`，不抛字符串 |
| 注释 | 只在"为什么"不明显时写；不写"是什么" |
| 日志 | 用 `logger.info/warn/error`，禁止 `console.log`（`scripts/` 例外） |
| 单文件行数 | ≤ 400 行，超了就拆 |

## 7. 规格没写时的裁决规则

按顺序套用，**不要发明新方案**：

| 情形 | 裁决 |
|---|---|
| 字段类型没写 | 参考同类字段；字符串一律 `text`，不用 `varchar(n)` |
| 错误码没列 | 用最近的语义（`VALIDATION` / `INTERNAL`），并在 PR 说明里记一笔 |
| 超时没写 | 外部 HTTP 5s，DB 3s，单轮 LLM 30s |
| 分页没写 | `page=1&size=20`，上限 100 |
| 排序没写 | `created_at desc` |
| 空值语义没写 | DB 用 `null`，API 出参保留 `null`，前端渲染 `—` |
| UI 间距没写 | 用 `--s2` / `--s4`，不发明新值 |
| 颜色没写 | 只用 `app.css` 里的令牌，不加新色 |
| 两个文档冲突 | 更靠后的任务卡（`15-tasks.md`）优先，其次 `14`/`07`/`05`/`04`/`02` |

## 8. 可以停下来的唯一情况

**只有这四种**可以停下来问人：

1. `T00` 的 9 项验证有一项失败（环境不兼容）
2. 同一个验收断言连续修 3 轮仍不过
3. 需要外部凭据（API Key）而 `.env` 里没有
4. 规格自相矛盾且 `§7` 的冲突优先级也无法裁决

**其他任何情况**——包括"这里我想加个功能""这个设计我觉得不好"——都按规格做，把意见写进 `docs/output/notes.md`，继续往下走。
