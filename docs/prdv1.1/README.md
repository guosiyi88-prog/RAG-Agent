## 一、为什么是这套目录（拆解维度）

一份"AI 能写完代码"的 PRD，和"人能评审"的 PRD 不是一回事。前者必须消灭四类歧义：

| 歧义类型 | 人评审能容忍 | AI 开发不能容忍 | 本套文档的解法 |
|---|---|---|---|
| **边界歧义** | "做个客服系统" | 不知道该建几个文件 | `02-architecture.md` 给出目标仓库**完整文件树**，每个文件一句话职责 |
| **接口歧义** | "返回会话列表" | 字段名猜错，前后端对不上 | `04-db.md`/`05-api.md` 给**逐字段**的权威定义 |
| **算法歧义** | "用混合检索" | 权重、阈值、边界全靠猜 | `07-retrieval.md` 给**可直译伪代码 + 全部常量** |
| **顺序歧义** | "分模块开发" | 先写哪个？依赖谁？ | `15-tasks.md` 给**任务 DAG**，每个任务独立可交付 |

由此得出 7 个拆解维度，对应 7 组文档：

```
① 边界 → 02-architecture   系统边界、文件树、进程模型
② 契约 → 03/04/05/06       技术栈、数据库、HTTP API、Agent 工具
③ 算法 → 07/08             检索、入库（含伪代码与常量）
④ 界面 → 09/10/11/12       令牌、用户端、坐席端、文案
⑤ 顺序 → 15-tasks          任务卡 + 依赖图 + 每卡验收
⑥ 守门 → 13/14/16/17       运维、验证、风险、给 AI 的总纪律
⑦ 人审 → 18-human-gates    5 个代码审查闸门（人读代码，不是跑程序）
```

## 三、三个"可直接落地文件"放在哪（推荐结论）

### 结论：写进 PRD，按关注点分三处，**不建 `middleware/`**

| 文件 | 写在哪 | 理由 |
|---|---|---|
| `package.json` | `03-tech-stack.md`（完整可复制） | 依赖版本是技术契约的一部分 |
| `sql/001_init.sql` | `04-db.md`（完整可复制） | 表结构是数据契约 |
| `docker-compose.app.yml` | `13-ops.md` §3.2（完整可复制） | 应用层编排；数据层 compose 归 `data/`，两者不合并 |

### 为什么不放 `middleware/`

1. **语义错位**。`middleware/` 在 Node/Fastify/Express 语境里专指 HTTP 中间件（鉴权、限流、日志）。把 `docker-compose.app.yml` 和 DDL 放进去，会让开发的 AI 误以为它们是请求链路的一部分，或者在 `middleware/index.ts` 里 import 它们。
2. **PRD 会失真**。规格文档必须自洽可读。把实现文件抽走，评审者读 PRD 就看不到真实表结构和依赖版本，PRD 不再是单一真源。
3. **改一处漏一处**。两份副本（PRD 一份、代码仓库一份）必然漂移。

### 如果确实需要"可直接复制的成品文件"

放在 `docs/prdv1.1/90-ready/`，文件名与仓库路径一一对应，并在文件头加一行注释：

```
// COPY TO: <repo-root>/docker-compose.app.yml
```

这样既不污染工程目录语义，又能让 AI 一键复制。**默认不建此目录**，需要时再建。

## 四、这份 PRD 的"可执行性"如何验证

三道检验，全部通过才算合格：

1. **闭卷检验**：只看 `15-tasks.md` 的某一张卡，能否在不读其他文件的情况下写出代码？→ 每张卡都带"依赖输入"与"产出文件"。
2. **字段检验**：随机抽一个 API 字段，能否在 `04`/`05` 找到唯一权威定义？→ 所有字段只在契约章定义一次，UI 章引用不重述。
3. **断言检验**：随机抽一条验收，能否写成一条可运行的命令或断言？→ `14-verification.md` 全部为命令或 `expect()`。

## 五、版本与命名约定

| 约定 | 规则 |
|---|---|
| 文档编号 | 两位数前缀，修改时只增不改号 |
| 表格字段名 | 一律用 `snake_case`（与 PG 一致），前端转 `camelCase` 只在 API 层做一次 |
| 常量 | 全大写 `SCREAMING_SNAKE`，集中定义在 `src/config.ts` |
| 时间 | 一律 UTC 存储，`timestamptz`；展示层按用户时区 |
| 语言码 | `zh / en / de / nl / es`，两位小写 |
| 金额 | `numeric(10,6)` USD，不存浮点 |
| 路径 | 文档内引用仓库路径一律从仓库根写起，如 `src/api/chat.ts` |
