**重建语义**：`001_init.sql` 开头 `drop view → drop table → drop function → drop sequence`，再 `create`。
这**不是** `create if not exists`——`make reset` 要求"恢复干净库"，旧结构漂移和脏数据都必须消失（`sql/001_init.sql:5`）。
因此 **`make init` 与 `make reset` 都会清空业务数据**。

## 2. 十八张表：语义与关键约束

### 2.1 知识侧

| 表 | 语义 | 关键约束 / 索引 | 行 |
|---|---|---|---|
| `documents` | 一篇语料 = 一篇文档；`sha256` 唯一，用于幂等入库。**`09#05` 起正文进库**（`body`）：管理端录入/编辑的就是它，重建只依赖 `body` + `lang` | `lang` 五值 check；**`status ∈ pending/indexed/failed/archived`（`09#05` 加 `archived`：停用是终态，行与快照都留、检索不再命中）**；`sha256 unique`（同正文重复录入 → 409）；`version`（每次成功重建 +1）；`updated_at`；`(lang)`、`(status)` 两个索引 | 36 |
| `document_versions` / `document_version_chunks` | 索引版本快照（`09#05`）：一行 = 一次成功重建；`document_version_chunks` 的列与 `chunks` 一一对应（除 `id`），所以回滚就是 `insert into chunks (...) select ... from document_version_chunks` | 主键 `(doc_id, version)`；`fk (doc_id, version) on delete cascade`；快照里的 `embedding vector(1024)` 逐位保留 | 443 |
| `document_rebuild_jobs` | 重建作业（`09#05`）：`POST .../rebuild` 落一行 `running` 就返回 202，前端拿 `id` 轮询；单独一张表而不是 `documents` 上几列，因为"这次"与"上一次"必须能区分 | `status ∈ running/succeeded/failed`；`error` 沿用 `documents.err` 的码（`no_text_layer` / `empty_after_clean` / `embed_*` / `db_failed`）；`(doc_id, started_at desc)` | 474 |
| `chunks` | 检索最小单位，**双索引**：向量做跨语种语义、全文做术语精确 | `embedding vector(1024)`；`tsv` 是 `generated always as (to_tsvector('simple', content)) stored`（生成列不能 virtual，gin 要读实体列）；`hnsw (embedding vector_cosine_ops)`；`gin (tsv)`；`(lang)`；`(doc_id, seq)` | 57 |
| `fault_codes` | 故障码：**主键 `(code, product_line)`**，同一个码在不同产品线含义不同 | 五语 `desc_*` / `act_*` 各五列；`severity ∈ info/warn/fatal`；**`status ∈ draft/published/archived`（默认 draft，09#02）**——`/api/fault` 与对话快路只认 `published`，归档只改 status 不删行；`(status)` 索引；**`updated_at`（09#04）**：管理端列表/详情显示的"最后改动时间"，由四类管理端写操作显式维护（没有这一列就只能拿 `created_at` 冒充） | 79 |
| `product_lines` | 产品线字典（09#02 / D21）：管理端下拉的唯一来源，`code` 主键 | 暂不加外键到 `fault_codes.product_line`，先靠应用层校验 | 96 |
| `qa_gold` | 评测题集（30 题 + 多轮 5 题不在此表） | `expect_doc_id → documents(id) on delete set null`；`should_refuse` | 239 |
| `kb_drafts` | 未命中转 FAQ 的草稿（A5 预留，无 UI） | `source ∈ no_hit/manual/ticket`；`status ∈ draft/approved/rejected` | 212 |
| `skills` | SOP Skills（P1 预留，无代码读） | `name` 主键 | 277 |

**为什么 `chunks` 有两个检索索引而不是一个**：单靠向量，`E03`、`F21`、型号这类**精确串**在跨语种语义空间里
会被稀释；单靠全文，德语问句与荷兰语原文对不上。两路召回后融合（`07`）才是这一层的设计意图。

**`lang` 过滤的坑**：检索 SQL 必须写 `lang = any($n::char(2)[])`。缺 `::char(2)` 会退化成 `text[]` 比较，
**放弃 `chunks_lang_idx`**（`sql/001_init.sql:73` 明确记了这一条）。

### 2.2 会话侧

| 表 | 语义 | 关键约束 | 行 |
|---|---|---|---|
| `conversations` | 一次会话；`token_id` 是匿名令牌（不建外键，令牌可能已过期） | `lang` 五值 check（可空） | 90 |
| `messages` | 用户/助手消息，**只用于记录与回放，不作为上下文来源**（ADR-0002：上下文只活进程内存） | `role ∈ user/assistant/system`；`tool_names text[]`；`refused`；`latency_ms`；`trace_id uuid` | 106 |
| `citations` | 引用**快照**：`doc_title`/`doc_lang`/`page`/`snippet` 落库即冻结 | `message_id` 级联删；`chunk_id → chunks(id) on delete set null`（chunk 被删不影响历史可追溯） | 126 |
| `attachments` | 附件（P1 预留，无写入路径） | `message_id` 级联删 | 228 |

**快照语义为什么重要**：重新 `ingest` 会让旧 chunk 退场。如果引用只存 `chunk_id`，历史回答的"原文"
就会在下次入库后变成空指针。所以标题/页码/片段必须抄一份进 `citations`。

### 2.3 工单侧

| 表 | 语义 | 关键约束 | 行 |
|---|---|---|---|
| `staff` | 坐席（**人**，不是 LLM Agent） | `email unique`；`role ∈ agent/lead/admin`；`active` | 141 |
| `tickets` | 工单；单号由序列生成 `WT-YYYY-NNNN` | `reason ∈ no_citation/out_of_scope/low_conf/user_request`；`status ∈ open/claimed/escalated/closed`；`priority ∈ low/normal/high/urgent`；`assignee → staff` | 159 |
| `feedback` | 点赞/点踩（U6 预留，**无路由写入**） | `score ∈ (-1, 1)`，不做 5 星 | 203 |
| `ai_runs` | **每次模型运行**的轨迹（不是坐席） | `tool_calls jsonb`；`refused`；`cost_usd numeric(10,6)` | 260 |
| `eval_runs` | 一次评测的四项指标 + 明细 | `detail jsonb` | 251 |
| `audit_log` | 审计（当前只有工单补丁写） | `created_at desc` 索引 | 297 |
| `exports` | 导出件（A7 预留，501） | `conv_id → conversations on delete set null` | 308 |
| `settings` | 运行时参数覆盖层 | `key` 主键；`value jsonb` | 289 |

**工单号为什么用序列**：`max(id)+1` 在并发建单时会撞号；序列天然并发安全，且跨年不重置，
靠 `to_char(now(),'YYYY')` 前缀区分年度（`sql/001_init.sql:151`）。

**`closed` 不可逆**（本次实现比 v1.1 更严）：触发器对 `old.status = 'closed'` 的**任何 UPDATE** 都
`raise exception`。v1.1 只禁止"closed → 非 closed"，那仍然允许"闭单后补写 resolution / tags"篡改历史。
要补信息就新开一张关联工单（`sql/001_init.sql:183`）。

## 4. 触发器与函数

```sql
gen_ticket_no() → 'WT-' || to_char(now(),'YYYY') || '-' || lpad(nextval('ticket_seq')::text, 4, '0')
guard_ticket_status() before update on tickets:
  old.status = 'closed'                    → raise exception（不可变）
  new.status = 'closed' and old <> 'closed' → new.closed_at := now()
```

**为什么 `closed_at` 由触发器写而不是路由写**：工单可能被 `/api/console/tickets/:id`、未来的批量工具、
甚至手工 SQL 改动。把"闭单时间"绑在状态迁移上，只有一处真相（`sql/001_init.sql:192`）。

## 5. 索引口径

| 索引 | 类型 | 为什么是它 |
|---|---|---|
| `chunks_emb_idx` | `hnsw (embedding vector_cosine_ops)` | 与"向量已 L2 归一化"绑定；换距离算子（L2/IP）会让召回分数**不可比**，阈值 0.30 立刻失效 |
| `chunks_tsv_idx` | `gin (tsv)` | 全文精确召回（型号、故障码） |
| `chunks_lang_idx` | btree `(lang)` | 检索必带语言过滤；缺 `::char(2)` cast 会绕过它 |
| `chunks_doc_idx` | btree `(doc_id, seq)` | 按文档取相邻块（后处理扩上下文） |
| `tickets_status_idx` | btree `(status, due_at)` | 坐席队列的排序键就是这两列 |
| `documents_sha256` | unique | 幂等入库的判重键 |
| `citations_msg_idx` | btree `(message_id)` | 收尾时按助手消息取引用 |
| `audit_log_created_idx` / `ai_runs_conv_idx` / 其余 | btree | 排查与统计路径 |

## 6. seed（`sql/002_seed.sql`）

| 内容 | 数量 | 幂等键 |
|---|---|---|
| 坐席 | 3（`张伟` agent、`李娜` lead、`王强` admin，口令均 `wt-demo-2026`） | `staff(email)` |

| 故障码 | 3（`E03`/`E07` balcony、`F21` residential，五语齐） | `(code, product_line)` |

**两个已登记的 seed 问题**（详见 `16` §2）：

1. **`settings` 只有 `sla.hours` 被代码读**（`src/core/ticket-store.ts:80`）。其余 9 个键（含
   `retrieval.top_k`、`refusal.enabled`）目前**没有消费方**——检索参数全部来自 `src/config.ts`。
   所以"改 `settings` 就能调参"这句话现在只对 SLA 成立。
2. **jsonb 值写成了字符串**：`'5'`、`'0.30'`、`'true'` 都是 JSON **字符串**而不是数字/布尔
   （文件头注释甚至写了"数字不加引号"，但实现是加引号的）。读取方必须 `Number()` 转换。
