# 07 · 检索（as-built）

> 覆盖 `src/core/retrieval.ts`(647) + `fuse.ts`(111) + `query.ts`(45) + `embed.ts`(211) + `hash-embed.ts`(67)。
> 本章的**核心事实**：最终分不是归一化 RRF，而是 **归一化 RRF × 余弦相似度²**——
> 这是实现期对 v1.1 的一处勘误，改它必须同时改 `14` 的断言（见 §9）。

---

## 1. 两层，互不越界

| 层 | 做什么 | 明确**不**做 |
|---|---|---|
| 召回（`recall` / `recallVector` / `recallFts`） | 出候选、语言过滤、给该路**原始分** | 不融合、不归一化、不判阈值、不按 doc 去重、不截断、不分 `idx` |
| 融合与后处理（`fuseAndPostProcess` / `retrieve`） | RRF → 归一化 → 去重 → 截断 → topK → 分 `idx` | **不判阈值**（阈值比较属于调用方：`chat.ts` 的拒答判定） |

入口分层（越靠下越纯，便于单测）：

```
retrieve()                  完整检索：查询构建 + 降级 + 两路召回 + 融合后处理
  fuseAndPostProcess()      纯函数：只看候选，不碰 DB/网络
  recall()                  两路并行召回（内部调试接口用）
    recallVector()          embed(query) → recallVectorByEmbedding()
    recallVectorByEmbedding()  给向量就能跑（降级向量也走这里）
    recallFts()             纯 SQL，不碰模型
```

## 2. 语言视野（`LANG_SCOPE`，唯一真源）

| 提问语言 | 检索语言视野 |
|---|---|
| `zh` | `zh`, `en` |
| `en` | `en` |
| `de` | `de`, `en` |
| `nl` | `nl`, `en` |
| `es` | `es`, `en` |
| 未知 | 按 `en` 处理（宁可少召回，不要把五语副本全捞回来） |

**为什么必须过滤**：同一段内容有五语副本，在向量空间里挤在一起。不过滤时 top20 常被同一段内容的
五种翻译占满，等于只召回 1 条独立信息。每种语言都带 `en`：英文语料是公共底稿，术语最齐。

SQL 里的语言数组**只能**由这张表生成，不许在 SQL 里写 `array['de','en']`（写死之后加语言会漏改且不报错）。

## 3. 两路召回

| 路 | SQL 要点 | 分值口径 | 上限 |
|---|---|---|---|
| 向量 | `1 - (embedding <=> $1::vector)`；`order by embedding <=> $1`；`lang = any($2::char(2)[])`；`join documents d … and d.status <> 'archived'`（`09#05`） | 余弦**相似度**（`<=>` 是余弦距离） | 20 |
| 全文 | `ts_rank(tsv, plainto_tsquery('simple', $1))`；`tsv @@ plainto_tsquery(...)`；同样排除 `archived` | `ts_rank`（量纲与余弦**不可比**） | 20 |

> **排除写的是 `d.status <> 'archived'`，不是 `= 'indexed'`（`09#05`）**：改了正文还没重建的文档是
> `pending`，那会儿旧索引必须仍然可检索 —— 写成 `= 'indexed'` 会让"编辑一次"把这篇文档从检索里
> 静默摘掉，直到重建成功为止。

三个必须写对的地方：

1. **`<=>` 是余弦距离**，与索引 `chunks_emb_idx ... vector_cosine_ops` 绑定。换算子（L2/IP）会让
   分数与索引口径脱钩：分看着还在 0..1，召回顺序已经不可比。
2. **`$2::char(2)[]` 的 cast 不可省**：省了 PG 按 `text[]` 比较，`chunks_lang_idx` 用不上，
   小数据看不出（planner 一律 seq scan），上量后 P95 直接爆。
3. **`to_tsvector('simple', …)` 不做词干化**：德语 `Wechselrichter`/`Wechselrichters` 是两个词，
   荷兰语复合词切不开。全文路**只承担精确术语**（故障码、型号、规格数字），
   **不许**用同义词表/词干化去"补命中"——那等于在检索层偷偷做 query 改写，可解释性没了。

**两路并行**（`Promise.all`）：任一路抛错整体抛错，不返回"半路成功"（半路成功会被下游当成"这一路没命中"）。

## 4. 查询构建（`buildQuery`）

| 条件 | 行为 |
|---|---|
| 当前问题空白 | 返回 `""`（调用方据此直接返回空结果，**不打嵌入接口**） |
| 当前问题长度 **≤25** 字符 **或** 无实词（连续 3 个字母/汉字） | 拼上一轮：`上一轮 + "\n" + 当前` |
| 其它 | 原样返回当前问题 |

**只在"这一句自己活不了"时借上一轮**：每轮都拼会让 query 一轮一轮漂移，到第五轮它描述的是
"整段对话的平均话题"。**不改写、不翻译**（ADR-0003）：改写要多一次模型调用（+~1.5s），
翻译会丢术语（`Wechselrichter`、`WT-ESS-5K`），且错在日志里看不出来。

## 5. 融合：带权 RRF

```
score(chunk) = Σ_paths  权重 / (k + rank0 + 1)
k = RRF_K (默认 60) · 向量权重 0.8 · 全文权重 0.2
```

- 只累加该 chunk **实际命中**的那几路；缺 key ≠ rank 0。
- 排序确定性：分数降序，**平分按 `chunk_id` 升序**（不靠 Map 迭代顺序，否则同一输入两次给出不同编号）。
- 理论上界由公式算：`maxPossibleScore() = vecWeight/(k+1) + ftsWeight/(k+1)` ≈ **0.016393**。
  **不许写成魔数**：调权重（如 FTS 提到 0.35）时分母必须跟着动，否则所有归一化分集体偏低，
  症状是"调完权重拒答变多了"。

---

## 6. 归一化与相关性整形（本仓最重要的一处算法）

```ts
normalized = min(1, max(0, rawRrf / maxPossibleScore()))
finalScore = normalized * cosine²          // 无余弦（全文路独有片段）时 finalScore = normalized
```

**为什么不能只用归一化 RRF**：它是**纯排名**信号。向量路只要返回了行，第 1 名就存在，
归一化必然给 0.8（单路第一）或 1.0（两路都第一）——与问题相不相关完全无关。
实测（同一份五语语料）：`Wechselrichter Wirkungsgrad` 余弦 0.65、`今天天气怎么样` 余弦 0.42，
两者的归一化 RRF **都是 0.8**，阈值 0.30 等于没有阈值（`retrieval.ts:441`）。

**为什么平方**：多语嵌入有 ~0.4 的噪声地板（无关文本也能到 0.42–0.46），不压缩时
"0.42 的无关"与"0.65 的相关"只差 0.23；平方后变成 0.18 与 0.42，0.30 正好落在中间。

**全文路独有片段按余弦 1 处理**：字面命中精确术语本身就是相关，不能因为"没有向量"判成无关。
这也让 `fallback="fts_only"` 时全文路仍然可用。

> 这是**唯一**一处分值整形。改它必须同时改 `14-verification.md` §3 的断言，否则门禁会"照着旧口径通过"。

## 7. 后处理（顺序不可换）

| 步 | 动作 | 换序会怎样 |
|---|---|---|
| ① | RRF 融合 | — |
| ② | 归一化 × 余弦² | 只用归一化 → 阈值失效（§6） |
| ③ | 按分降序；平分按 `chunk_id` 升序 | 测试会抖、引用编号会变 |
| ④ | **按 doc 去重，每文档 ≤3 条**（在分数序上数） | 先截断再去重会丢掉本该补位的其它文档 |
| ⑤ | 截断 `CONTENT_MAX_CHARS=600`（UTF-16 `slice`） | 放在去重前不影响排序但不必要 |
| ⑥ | 取 `topK`（默认 5）；**不补空** | 补一条空片段 = 伪造引用 |
| ⑦ | 分配 `idx = 1..n` 连续无空洞 | 断号的角标在正文里就是坏引用 |

`resolveTopK`：非有限值/非正数一律回落到配置值（`slice(0, NaN)` 返回空数组，会让"少配一个参数"
静默变成"检索没结果"）。

## 8. 降级与错误口径

| 情况 | `fallback` | 行为 |
|---|---|---|
| 正常 | `none` | — |
| 嵌入超时/不可用（`EmbedError` 非维度错） | `fts_only` | **换 `hashEmbed` 继续跑向量路**，并 `logger.warn` |
| 数据库不可用/超时（`57014`/`57P0x`/`08xxx`/socket 错误码/连接池超时文案） | `empty` | 返回空结果（**不抛**：慢库不该变成用户看到的 500） |
| 两路都空 | `empty` | 空结果 |
| 向量维度 ≠1024 | — | **抛出**（`EMBED_DIM_MISMATCH`）：数据事故必须炸 |
| 其它异常（SQL 写错、`42P01`） | — | **上抛** 500（把它降级成"没搜到"等于把事故藏进拒答话术） |

**`fts_only` 这个名字是历史包袱**：降级时向量路**仍然会跑**（用 hash 兜底向量），
标签描述的是"语义召回已不可信、实际靠全文兜住"，不是"把向量路关掉"。

**降级必须同时被日志、响应体、测试看见**：吞掉错误却不改 `fallback`，故障表现就是
"今天召回率莫名偏低"，谁也归因不了。

## 9. 嵌入后端

| 后端 | 触发 | 实现 | 质量 |
|---|---|---|---|
| `dashscope`（默认） | `EMBED_BACKEND=dashscope` + 有 Key | `POST` text-embedding-v3，`dimension=1024`，**批 10 条**，单批超时 **15s**，失败重试 | 可用于验收 |
| `hash`（兜底） | 无 Key / 显式配置 / 运行期降级 | FNV-1a 32bit → 1024 维 → L2 归一化；CJK 逐字切、西文按词切、统一小写 | **只保证确定性**，hit@5 = 0 |

**hash 后端不许加特征工程**（词干化/同义词/停用词）：加了之后召回失败无法归因——
到底是兜底向量的锅还是检索公式的锅，评审时分不清。

维度锁死：`EMBED_DIM=1024`（`embed.ts:17`）与 `chunks.embedding vector(1024)` 必须一致；
查向量维度不符时**整个请求失败**，不截断、不补齐。

## 10. 时间预算

| 段 | 预算 | 实测来源 |
|---|---|---|
| 查询嵌入（网络） | — | `timings.embed_ms` |
| 向量召回 | — | `timings.vector_ms` |
| 全文召回 | — | `timings.fts_ms`（与向量并行，按墙钟算） |
| **融合 + 后处理** | **≤5ms** | `timings.fuse_ms`（纯 CPU，不碰 DB/网络） |

三个 `timings` 都进 `/internal/search` 的响应体，是排查"慢在哪一段"的唯一依据。
