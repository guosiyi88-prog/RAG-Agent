# 12 · 五语文案（as-built）

> 唯一真源：`src/static/i18n.json`（**五语 × 127 key**）。
> 读取点：`src/core/i18n-table.ts`（core 侧唯一）。校验：`scripts/check-i18n.ts`（五条断言）。
> 下发：`GET /api/i18n/:lang`。前端兜底：`lib/i18n-chrome.js` + `lib/i18n-de.js`。

## 1. 表结构与 key 分组（127 = 12+4+23+11+15+18+13+8+6+5+12）

| 组 | 条数 | 覆盖 |
|---|---|---|
| `common.*` | 12 | 确定/取消/关闭/返回/重试/复制/已复制/加载中… |
| `nav.*` | 4 | 四个 Tab |
| `chat.*` | 23 | 标题、状态、发送、错误、连发灰字、工单卡、转人工… |
| `cite.*` | 11 | 抽屉标题（带 `{i}/{n}`）、页码、语种、上一条/下一条 |
| `fault.*` | 15 | 输入提示、严重度、步骤、来源、未找到、最近查询、"问 AI" |
| `ticket.*` | 18 | 建单表单、单号、配额、状态四态、查进度 |
| `me.*` | 13 | 语言、清除数据、版本、关于 |
| `a11y.*` | 8 | 发送/关闭/角标/Tab 的读屏标签 |
| `toast.*` | 6 | 在线/离线/已复制… |
| `lang.*` | 5 | 五个语种的自称（`Deutsch` / `Nederlands` …） |
| `quick.*` | 12 | 快捷问题 |

**`zh` 是主源，`en` 是回落语**：这两门缺一门就算表坏了（`i18n-table.ts:60`）。

---

## 2. 回落链（服务端做，前端只拿结果）

```
请求语言的一条 key
  → 缺失取 en 的同一条
  → 再缺：下发给前端时用 key 原文；拼进用户可见正文时**不输出这一行**
```

两个函数，**故意不合并**：

| 函数 | 用途 | 缺 key 时 |
|---|---|---|
| `mergeMessages(table, lang)` | 下发整张表（`/api/i18n/:lang`） | 回落成 **key 原文**（开发期可见，能一眼看出没翻译） |
| `t(lang, key)` | 服务端拼**用户可见文本**（故障码快路末行 `fault.source`） | 返回 **`null`**（宁可少一行，也不能在德语答复里露出 `fault.source`） |

**合并以 `zh` 的 key 集合为基准**：`zh` 里没有的 key 不下发（多发的 key 只会让"表里有、页面没有"变成噪音）。

---

## 3. 服务端

| 项 | 事实 |
|---|---|
| 读取时机 | `i18n-table.ts` 的 **import 期**（同步 `readFileSync`）→ 坏文件让**进程起不来**，而不是第一条请求 500 |
| 校验强度 | 只保证"一层 key → 字符串" + `zh`/`en` 两根基石在；条数/占位符/CJK 交给 `check-i18n.ts`（提交前拦） |
| 运行期改表 | 要**重启**才生效（进程内唯一一份表，只读） |
| 接口 | `GET /api/i18n/:lang` → `{ ok: true, data: { lang, messages } }` |
| 未知语种 | **400 VALIDATION**（不静默回落 `en`：否则"五语"永远无法证伪） |
| `de-DE` 归一 | 由浏览器侧 `normalizeLang` 先归一到两位；服务端只认两位（两处都归一 = 两套规则） |
| 令牌 | 不要（文案是公开界面文本，且弱网下要先点亮界面再取令牌） |

---

## 4. 坐席端例外：**只做中文**

`console.*` 这类 key **不许**出现在 `src/static/i18n.json` 里，`check-i18n` 的断言 e 会硬失败。

理由：内部工具 + 时间预算（`11-ui-console.md` 顶部）。实现上坐席端 `console.html` 里全是中文硬编码，
不走文案表——把它塞进表会让人误以为"坐席端也支持五语"，而实际上没有任何切换入口。

---

## 5. 前端

| 项 | 事实 |
|---|---|
| 取表 | `boot()` 与切语言时 `GET /api/i18n/:lang`；失败**不弹错**（文案不该卡死页面） |
| 挂点 | `[data-i18n]`（textContent）/ `[data-i18n-ph]`（placeholder）/ `[data-i18n-aria]`（aria-label） |
| `t()` 查找顺序 | 远程合并表 → 离线兜底（`i18n-chrome` → `i18n-de`）→ key 原文 |
| 为什么不用 `??` 逐 key 回兜 | 服务端合并结果里**一定有**每个 key（最后是 key 原文），再 `??` 会盖掉"服务器故意给的 key"，缺翻译看不见 |
| 默认语言 | `de`（德语市场最先全量抽检，断网时比中文更贴近现场） |
| 回落链 | `localStorage` → `navigator.language` 前两位 → `en` |
| 切语言 | 不刷新页面，改 `<html lang>` + 全部挂点 + `<title>` + 三个次级视图重渲染 |

## 6. 校验脚本：`scripts/check-i18n.ts` 五条断言

任一不达标 → 退出码 1。

| # | 断言 | 为什么是硬的 |
|---|---|---|
| a | 五语 key 集合与 `zh` **完全一致**，总数 = 127（按 `12+4+23+11+15+18+13+8+6+5+12` 算式断言，不按记忆） | 历史上 140 / 142 / 实测 127 都出现过 |
| b | 没有空值 / `null` | 空值在页面上是一块空白，比显示 key 原文更难查 |
| c | `de/nl/es` 不得出现 **CJK** | 机翻漏译或文件贴错；荷兰客户看到汉字会以为产品不是给他的 |
| d | 占位符出现次数与 `zh` 一致 | 少一个 `{n}` 就是"引用 1 / "这种半截句子 |
| e | 不得出现 `refusal.*` 与 `console.*` | 拒答话术唯一真源是 `core/refusal.ts`；坐席端不进用户端表 |

**只告警不失败的一条**：译文显示宽度 > `zh × 2.2`。当前 **40 条告警**，集中在 `es`（西班牙语长词）。
德语长词靠 `<html lang>` + `hyphens:auto` 断词解决（`09-ui-tokens.md` §5），不靠缩字号。

同族脚本 `scripts/check-terms.ts`：术语逐条对齐 + `de/nl/es` 片段不得含汉字。
**纯文件检查，不必起数据层**，所以它能在 CI 的第一秒就红。
