## 一、为什么单独立一版

`docs/prdv1.2/` 的 §七 写死了维护纪律：**不许在 v1.2 里写实现计划**。管理端是二十多天里最大的一次边界变更（D8 推翻 `01-scope.md` §5 第 1 条"明确不做登录/注册"），计划总得有个家。这个目录就是那个家，v1.2 保持"只描述已存在的东西"，两者不混。

## 二、阅读顺序

`README.md` → `scope-delta.md`（改什么） → `acceptance.md`（怎么算过） → `.scratch/09-admin-console/spec.md`（工单为什么这么拆）

## 三、落地后的回写纪律（照 v1.2 §七 放大）

1. 改 DDL → 改 `prdv1.2/04-db.md`；改路由/错误码 → `05-api.md`；改坐席端 UI → `11-ui-console.md`；改门禁 → `14-verification.md`；改任务账 → `15-tasks.md`。
2. 新增能力占**两个位置**：`prdv1.2/01-scope.md` 加一行 + `15-tasks.md` 加一张卡。
3. **v1.3 只记计划与验收**。代码落地后，结论搬到 v1.2，v1.3 对应条目勾掉并写一行"已落地，见 v1.2 X 章"。
4. 发现文档与代码不一致：先在 `prdv1.2/16-risks-errata.md` §2 登记一个新 E 编号，再改文档。
